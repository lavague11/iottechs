Single-file field commission calculator — architecture, formulas, catalog, and pricing

1 · What it is

One HTML file, commission-calculator.html. No build step, no dependencies, no network calls, no storage. Open it from a phone home screen, a laptop, or a folder on a USB stick and it works offline.

Purpose
Price an ADT/SafeStreets deal at the door and see the commission before leaving
Stack
Vanilla HTML, CSS, JS. No libraries.
Size
~55 KB, single file
Design
VAULT DARK — cream #FAF8F4, slate #2C3347, gold #C9A96E, ink #0B0F1A
State
Entirely in the DOM. Reload clears everything. Nothing is persisted anywhere.
Deploy
Drop the file on any static host, or mount it inside the FSM platform as a route

2 · The money model

Every number the tool shows comes out of this chain. This is the part to get right if it's ever rebuilt.

Net funded MMR   = MMR + cost of service        (cost of service is negative)
Gross funding    = net funded MMR × tier multiple
Budget           = gross funding + activation

Cost of goods    = Σ (new qty × part cost) + Σ (total qty × labor)
                     existing units charge labor but no part cost

Overhead         = admin + attrition + merchant + ADC
Attrition        = gross funding × tier attrition %

Base             = budget − cost of goods − overhead + custom labor/parts margin

Commission at cost       = base                          (free system — you credit all retail)
Commission (this deal)   = base + (retail − credit given)
Commission at full retail= base + retail                 (no credit)

Customer pays    = activation + retail − credit given    (activation is due in every scenario)
Equipment margin = retail − cost of goods
The credit is the only lever between the two ends. Every dollar credited to the customer comes out of the payout dollar for dollar. The three scenario buttons are just three points on that line.

Fundable bands

The MMR must land inside a band or the deal won't fund. The band is whichever is higher — the package sold, or the devices actually on the job.

4 · Screen layout

Main page is four cards. Everything set once and forgotten lives behind Settings in the header.

  1. Deal — rep, customer, credit tier, monthly rate (typeable, with −/+), activation, package, Nest Aware
  2. The numbers — budget / cost / retail / margin tiles, the three scenario buttons, credit field, and a collapsed full breakdown
  3. Equipment — search, Existing toggle, Best Sellers, then seven categories. One open at a time.
  4. Cart — editable quantity per line

Settings holds fees, tier rates and attrition, custom labor & parts, and the full equipment pricing grid (labor / cost / retail for all 41 items).

Sticky bar — three views

Cust / Rep / Admin toggle, Clear, and Save. Save downloads whichever document matches the view.

ViewBig numberSeesNever sees
CustWhat the customer paysRetail per line, equipment total, monthly rate, savingsCost, margin, commission, Settings
RepRep's own commissionTheir commission across the three credit scenarios, credit field, customer's total, retailCost of goods, company margin, full net commission, Settings
AdminNet commissionEverything, plus the rep's cut in the subline—

Rep commission is a share of the deal's net commission — the split lives in Settings, default 50%, with an optional per-deal minimum. Rep-view color thresholds are scaled to the split (red under $150, orange to $200, yellow to $250, green above), so the signal reads the same as Admin's $300/$400/$500 bands at a 50% cut.

  • Internal — big number is the net commission, color-coded: red under $300, orange to $400, yellow to $500, green above. Cart shows cost, retail, and margin. Save downloads the internal deal summary.
  • Customer — big number becomes what the customer pays. Save downloads the customer proposal.
Hard rule: the customer never sees cost. In Customer view every one of these must be hidden or swapped to retail — the numbers card (budget, cost, margin, scenarios, credit), the Settings button and sheet, the per-row cost subline in the picker and Best Sellers, the equipment card footer, and the cart's margin lines. Anything added later that displays cost, margin, or commission needs the internal-only class or a custView branch. Audit both when touching the equipment renderer.

Promo codes (Customer view)

In Customer view the credit is no longer a free-text field — the customer owes full retail unless a valid code is entered. Codes are case sensitive and always uppercase; a lowercase entry is rejected with a message rather than silently matched.

CodeDiscount
IOT500$500.00
IOT1000$1,000.00
IOT1500$1,500.00

The table is the PROMOS object at the top of the script — add a key to add a code. The discount is capped at the equipment retail, so a code larger than the job zeroes the equipment but never produces a negative balance or credits the activation. Editing the code field after applying clears the discount, so a half-typed code can't leave a stale credit on screen. In Rep and Admin views the credit stays a free-text field, since those users set credit directly.

Existing equipment

The Existing checkbox in the equipment header reveals a second counter per row. Existing units charge labor (the tech still converts them) but no part cost and no retail. Unchecking clears the counts so nothing hides.

5 · Code map

Everything is in one <script> block at the bottom of the file, in this order:

BlockWhat it does
TIERS, PKGSRate tables. Edit here to change multiples or package pricing.
CATSThe catalog. Each item: n name, pn part #, e part cost, l labor, r retail (0 = derive), s smart flag, qn default qty.
EQUIPFlattened catalog with a stable global index i. Every DOM id ends in that index.
BESTBest Sellers — references to the same objects, not copies. Quick-add mirrors.
ELCached DOM nodes, built once. calc() reads from here, never getElementById.
calc()The whole model. One pass over EQUIP, then funding, scenarios, cart, breakdown. Returns an object the document generators consume.
schedule()requestAnimationFrame debounce — one repaint per burst of typing.
saveCustomer() / saveInternal()Build a standalone branded HTML document and trigger a download.

ID conventions

PatternElement
qn{i} / qe{i}New / existing quantity for item i — the source of truth
l{i} / e{i} / p{i}Labor, part cost, retail price (in Settings)
t{i} / s{i} / row{i}Price display, cost subline, row container
bp{i} / bsub{i} / brow{i}Best Sellers mirrors of the above
[data-cq] / [data-bs]Cart and Best Sellers quantity inputs — write through to qn{i}
Best Sellers and the Cart are views, not separate state. They write into qn{i} and read back on the next calc. Never store quantity in two places.

6 · Common edits

Change a price permanently

Edit the item's e, l, or r in CATS. Editing in the Settings screen changes the current session only — a reload restores the file's values.

Add a device

Add an object to the right category in CATS. Set s:1 if it's a smart/video device, which affects the fundable band and triggers the package auto-upgrade. Everything else — DOM, cart, search, documents — builds from the catalog automatically.

Add it to Best Sellers

Append the exact item name to BEST_NAMES. It renders in catalog order, not list order.

Change what a rep can see

Add the class internal-only to any element to hide it in Customer view.

Rate or fee change

TIERS for multiples and attrition, PKGS for cost of service and standard rate, and the default value attributes on fAct, fAdm, fMer, fAdc for fees.

8 · Known issues and history

  • Door/window sensor was a 3-pack price. The original Payscale sheet listed $34.50 in a per-unit column. The ADT sheet has it at $12.64 each. Any older calculation using $34.50 per unit is wrong.
  • Nine items have no published retail. Hybrid panel, AT&T radio, three desk mounts, wall mount, and Command Labor are all derived at cost + 30%. These need real numbers.
  • Margin % is margin over retail, not markup over cost. A cost + 30% item shows 23% margin. That's correct, just easy to misread.
  • Nothing persists. A reload loses the deal. If this becomes a problem, the fix is to serialize the qn/qe values plus the deal inputs into localStorage or the FSM platform's job record.
  • Attrition is held, not lost. It's withheld at the tier rate and released under the funding agreement. The tool deducts it in full, so the commission shown is conservative.

9 · If it moves into the FSM platform

  1. Catalog to the database. CATS becomes an equipment table with cost, labor, retail, and the smart flag. The tool fetches it instead of hardcoding.
  2. Rates to a settings record so a change propagates without editing a file.
  3. Save writes a job record rather than downloading an HTML file — deal inputs, line items, credit, and the computed commission.
  4. Customer proposal feeds the proposal builder instead of being its own document.
  5. Keep calc() intact. It's pure — inputs in, numbers out. Port it verbatim and the math stays trustworthy.
